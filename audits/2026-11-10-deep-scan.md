# Bops fork: deep scan, 2026-11-10

Asked for by Kevin. Done by the lead (Claude) in a cloud session. The plan that closes these findings is [../BUILD_PLAN_V2.md](../BUILD_PLAN_V2.md).

**This repository is public.** Findings that would help an outsider are kept in a private file (IDs BX-01 to BX-06, in Kevo919/agent-desktop-hub, branch `team`, `audits/2026-11-10-bops-private-findings.md`). They are named here by ID only.

## How this was done, and its limits

- **Read:** the whole `team` board; on `windows-port` (e54bbab): the request gate (`proxy.ts`), the desktop shell settings, the update code, phone pairing, the Repos runner's permission flow, the server setup script, all four workflows, the Android manifest and network rules.
- **Ran:** `npm audit` against `package-lock.json`; a comparison of `windows-port` with upstream `main`.
- **Not done:** the fork adds about 60,000 lines across 585 files. I did **not** review them line by line. Nothing was run on the PC, the server or a phone. Task BG-09 is the full review this scan could not be.
- I could not see GitHub settings or which pull requests are open.

## The short version

1. **The code is ahead of everything else.** 126 pull requests in a week. What is installed on the PC, what has been tried live, and what has been tested are all well behind what is merged.
2. **The base it stands on has moved.** The fork is 172 commits behind the original project and carries libraries with known security advisories, one of them critical.
3. **Nobody is leading.** The lead's status file is from Nov 3, a pull request has waited for a security review since Nov 8, and one agent has been checking an unchanged board every hour for days.
4. **The public board holds things it should not** (BX-01, BX-02).

The original project's safety design is careful (window-only token, origin checks, owner-only approvals, sandboxed windows), and the fork has mostly kept to it. The risk is in the volume of new code that has had no second look, not in an obvious hole I can point to.

Severity: **Critical** = fix before relying on it. **High** = before daily use. **Medium** = before calling it finished. **Low** = tidy-up.
