## Summary

The Android companion can now keep several Bops servers and switch between them. Existing installations migrate to "My Bops" without re-pairing. All changes are confined to android/; no third-party libraries were added.

- Add, select, rename and remove servers from setup or the WebView's Servers button.
- QR links display the address for confirmation; successful pairing adds or updates the matching address.
- Destroy the previous WebView, clear its cookies, and set only the chosen pairing cookie before loading.
- Poll each paired server independently every 60 seconds with its own cookie and first-run notification history. Notifications show the server name and open the correct server.
- Preserve address/origin restrictions, HttpOnly/SameSite=Strict/Secure cookies, current-page microphone permission and external browser links. Revocation removes only the affected code; stale failures cannot erase a replacement code.
- Include the Gradle wrapper and platform-only regression tests.

## Tested

- Windows: `cd android; .\gradlew.bat assembleDebug assembleDebugAndroidTest lintDebug` — passed; lint 0 errors, 17 warnings.
- Android API 35 emulator: platform instrumentation suite passed migration/idempotence, list operations, history isolation, stale and isolated revocation, Tailscale/HTTPS address policy and scheme/host/port checks.
- Local HTTP fixtures: per-server cookies, first-run suppression, separate notifications for identical keys, server names, failure isolation and 401/403 revocation. Fixtures call polling directly rather than waiting for the scheduler.
- Emulator UI: server switcher, switching between two hosts, old-cookie removal, selected-cookie installation, QR address confirmation without saving before Connect.
- Inspected final switcher screenshot; fixed Android 15 status-bar overlap.
- Independent static review and `git diff --check` passed.

## Not tested

- Successful pairing against live Bops servers over real Tailscale or public HTTPS.
- Physical-device microphone calls, external browser navigation, reboot/background battery behavior, or a full 60-second polling schedule.
- Linux/macOS wrapper execution (wrapper scripts generated by Gradle; Windows build verified).
