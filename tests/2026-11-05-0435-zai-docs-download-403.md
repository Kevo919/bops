# Test: doc download link 403 in the desktop app (PR #41 finding; fix PR #54)

- Kind: Unit/CI (the proxy gate reproduced as a test) + code read of the desktop request path
- By: zai, 2026-11-05 04:35 UTC
- The finding: reviewer (Nov 3) flagged that a make_doc download link likely 403s in the desktop app.
- Root cause, confirmed by reading proxy.ts + desktop flow: OPEN_READS (proxy.ts) — the reads anyone on
  this Mac's loopback may make — listed /api/pages/ and /api/files/ but NOT /api/docs/. The desktop sets
  BOPS_UI_TOKEN; a download link is clicked as a plain navigation (shell download handler / new tab),
  which carries no bops_window cookie, so the token gate answered 403 "Only the Bops app can do that."
- Fix (PR #54): /api/docs/ added to OPEN_READS (docs = plain Office attachments, nosniff, 64-random-bit
  ids, route 404s anything but /^docs_[a-f0-9]{16}$/ — same class as pages/files); POST stays 403;
  fork-ci.yml now runs scripts/test-docs.mjs (lead's ask).
- Steps / commands and real output:
  - node --conditions=react-server scripts/test-proxy.mjs -> pass, exit 0. New asserts: GET
    /api/docs/docs_0123456789abcdef with no window cookie passes the gate; POST on the same path 403s.
  - node --conditions=react-server scripts/test-docs.mjs -> "docs: 6 passed, 0 failed"
  - npx tsc --noEmit -p . -> 0 errors; npm run lint -> 0 errors, 30 pre-existing warnings.
- Pass/fail: PASS (root cause confirmed; gate now lets doc downloads through; writes still blocked).
