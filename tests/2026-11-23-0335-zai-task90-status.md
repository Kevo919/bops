## A product bug on the Windows port (found and fixed, commit 921b35c, not reviewed)

`app/api/skills/route.ts`, the `import` action, took only paths starting with `/`. Every folder on Windows starts with a drive letter, so **importing a skill or app from a folder was refused on Windows** with "Pick a folder.". The audit had this down as a failing suite; it is a failing app.

One-line fix: `path.isAbsolute(path)` in place of `path.startsWith("/")`. On macOS and Linux `isAbsolute` accepts exactly what the old check did. On Windows it also accepts a drive letter or a network share. A path that is not a folder is still refused further on, where the folder is opened.

Verified on the Windows PC: `npx tsc --noEmit -p .` exit 0 with no output; `npm run lint` exit 0, 0 errors, 35 warnings, none on a line this adds (one is in `test-chat-compact-ui.mjs`, on an upstream line of 30 Oct). With the fix, `test-skills`'s import check is no longer refused for a path under the scratch folder.

Not verified: not run on macOS or Linux; the import is not finished by that check on Windows yet (it next differs on a link that points inside the folder); not tried in the app itself. **This is a change to the app and needs the lead's review.**
